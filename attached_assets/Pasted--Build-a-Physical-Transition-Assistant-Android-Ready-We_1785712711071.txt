# Build a Physical Transition Assistant — Android-Ready Web App

## PROJECT OVERVIEW

Build a mobile-first application designed to help a user who struggles primarily with:

* Executive dysfunction
* Task initiation
* Physical transitions between activities
* Getting out of bed
* Getting stuck in one location for long periods
* Phone distraction
* Freeze states
* Overwhelm from large to-do lists
* Burnout from trying to maintain overly ambitious routines

This is NOT a generic habit tracker.

The core concept is:

> **Don't think about the whole day. Just move to the next station.**

The user's home is turned into a sequence of physical checkpoints.

The smartphone is the central controller and "breadcrumb."

Each physical checkpoint has an NFC tag.

The user physically moves to a location, scans the NFC tag, and the app automatically starts the task. The user then places the phone on a magnetic wall-mounted phone parking station and physically leaves the phone behind.

The user performs the task.

The user returns to the station, retrieves the phone, and scans the SAME NFC tag again.

The first scan means:

> START

The second scan means:

> COMPLETE

The app should understand the state of the checkpoint and automatically determine whether a scan means starting or completing the task.

The user should not have to manually select "Start Task" or "Complete Task" during normal operation.

The goal is to minimize cognitive friction.

---

# IMPORTANT TECHNICAL REQUIREMENT

Build the application as a React + TypeScript web application that is architected to later be packaged as a genuine Android application using Capacitor.

The application should be designed with a clean separation between:

1. Core application logic
2. UI
3. Database/persistence
4. NFC abstraction layer
5. Android/native functionality

Do NOT pretend that ordinary browser JavaScript can reliably:

* Read NFC tags on all Android devices
* Run persistent alarms in the background
* Lock the Android device
* Prevent access to other applications
* Maintain full-screen notifications indefinitely

Instead, create clean interfaces/abstractions for these capabilities so that the web version can use simulation mode, while a future Capacitor Android layer can provide the real native functionality.

The app must work fully in "Simulation Mode" without real NFC hardware.

# NFC SYSTEM

Each physical checkpoint has ONE NFC tag.

The same tag is scanned twice.

First scan:

If checkpoint status is WAITING:

→ Start checkpoint.

Second scan:

If checkpoint status is IN_PROGRESS:

→ Complete checkpoint.

Example:

Station 2 NFC tag:

First scan:

"Stretch + foam roll started."

Timer automatically starts.

User puts phone on magnetic station.

User leaves.

User performs task.

User returns.

User scans same NFC tag.

App detects:

checkpoint status = IN_PROGRESS

elapsed time = 12 minutes

App marks checkpoint as COMPLETED.

The user should not have to press buttons during normal operation.

# NFC TAG REGISTRATION

Create a dedicated Settings/Admin section:

NFC TAG MANAGER

Allow the user to register physical tags.

Flow:

1. Tap "Register New NFC Tag"
2. User scans an NFC tag
3. Application reads the tag's unique identifier
4. Display the identifier
5. User selects which checkpoint it belongs to
6. Save the association

Example:

NFC ID:
04:8A:23:91

Assigned to:
Station 2 — Stretch + Foam Roll

Store the mapping in the database.

The application should NOT require the user to write information onto the NFC tag.

The tag's unique ID is the identifier.

Allow the user to:

* Register tag
* Reassign tag
* Replace tag
* Unregister tag
* Test tag
* View tag ID

If the same NFC tag is scanned twice, it should toggle between START and COMPLETE based on the current checkpoint state.

# CHECKPOINT STATE MACHINE

Each checkpoint should have a state.

Possible states:

WAITING

IN_PROGRESS

COMPLETED

MISSED

SKIPPED

CANCELLED

The normal state flow is:

WAITING
↓
IN_PROGRESS
↓
COMPLETED

A checkpoint can become MISSED if the user fails to complete it within its expected window.

A missed checkpoint should NOT be permanently lost.

The user should be able to complete a missed checkpoint later on the same day.

# FREEZE / EXECUTIVE DYSFUNCTION INTERVENTION SYSTEM

This is a core feature.

The system should detect when the user is stuck at a checkpoint.

Example:

NEXT ACTION:

💻 GO TO DESK

If the user does not progress for a configurable amount of time:

After 5 minutes:

"Still here?"

"Let's make it smaller."

"Just stand up."

After another configurable period:

"You're stuck. That's okay."

"What is making this difficult?"

Options:

🟢 I'm tired

🟡 I'm overwhelmed

🔵 I'm distracted

⚪ I don't know

Based on the selection, provide an appropriate intervention.

If TIRED:

"Let's switch to Reduced Mode."

If OVERWHELMED:

"Forget the whole task."

"Just take one step toward the station."

If DISTRACTED:

"Put your phone on the station."

If DON'T KNOW:

"Your only task is to stand up."

The system should reduce the next action to the smallest possible physical transition.

The philosophy is:

> Action first. Thinking later.

# PHONE PARKING CONCEPT

The physical system uses magnetic wall-mounted phone parking stations.

The user has a magnetic phone case or magnetic ring.

Each checkpoint has a magnetic parking spot.

The intended physical interaction is:

1. Arrive at checkpoint.
2. Scan NFC.
3. Task automatically starts.
4. Place phone on magnetic wall station.
5. Leave phone behind.
6. Perform task.
7. Return.
8. Pick up phone.
9. Scan same NFC tag.
10. Task completes.
11. Phone shows next checkpoint.

The application should visually communicate:

📱 PARK YOUR PHONE

when appropriate.

This is a central part of the system.

# PHONE DISTRACTION / LOCK SYSTEM

Create a "Strict Mode" architecture.

The intended future behavior:

Once a checkpoint starts:

The phone becomes restricted until the checkpoint is completed.

The user should not be able to casually open distracting applications.

However, do NOT falsely implement this as a browser feature.

For the web prototype:

Display:

PHONE FOCUS MODE

"Your phone is parked."

For the future Android/Capacitor version:

Prepare a native integration layer that can eventually support Android restricted/kiosk/lock-task behavior where technically and legally possible.

Always allow an emergency override.

The user should be able to exit strict mode through an explicit override.

Record the override in history.

# ACCEPTANCE TEST

The application is considered successful when the following flow works in Simulation Mode:

1. User opens the app.
2. App displays the current next action.
3. User simulates Station 1 NFC.
4. Station 1 changes from WAITING to IN_PROGRESS.
5. The appropriate task begins.
6. User simulates Station 1 NFC again.
7. Station 1 becomes COMPLETED.
8. App automatically displays Station 2 as the next action.
9. User simulates Station 2.
10. Timer automatically starts.
11. User simulates Station 2 again too early.
12. App warns that the minimum duration has not been reached.
13. User can continue, complete anyway, or skip.
14. Missed checkpoints are recorded.
15. Missed checkpoints remain available later in the day.
16. Energy Modes change the active routine.
17. Freeze interventions trigger when configured.
18. Daily history records all events.
19. NFC tags can be registered and mapped to checkpoints.
20. The same NFC tag can start and complete a checkpoint based on its current state.

The final result should feel like a calm, intelligent "physical transition assistant" rather than a traditional productivity or habit-tracking app.

The core experience should always reinforce:

> **Don't think about the whole day. Just move to the next station.**
